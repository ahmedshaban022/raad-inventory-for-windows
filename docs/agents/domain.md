# Domain Docs

## Layout

This project uses a single-context layout:

- `GLOSSARY.md` at the project root.
- Architecture decision records under `docs/adr/`.

## Before exploring

Read the root glossary and ADRs relevant to the work.

If these documents are absent, proceed silently.
The domain-modeling workflow creates them when terminology or decisions
are resolved.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and test names.
For missing concepts, reconsider invented terminology or note a genuine
gap for domain-modeling.

## ADR conflicts

Explicitly identify any proposal that contradicts an existing ADR.
Name the ADR and explain why reopening its decision is justified.
